01 / THE BIG PICTURE

What is a Transformer?

A Transformer is a neural-network architecture introduced in the 2017 paper Attention Is All You Need. Its central idea is attention: a way for a model to decide which parts of its input are useful to one another. Transformer-based systems now appear in language-model families such as GPT, Llama, and Gemini, as well as applications involving images, audio, proteins, and games.

A text-generating language model repeatedly asks: given the tokens so far, what token should come next? A token may be a word, a word fragment, a space-related fragment, or punctuation. The model predicts one token, appends it to the context, and repeats. Fluent text is built from many of these small steps, rather than from a single prediction of the whole answer.

This page uses GPT-2 small, a 124-million-parameter, decoder-only Transformer. It is much smaller and older than today's leading models, but its components provide a useful introduction. The 2017 Transformer included both an encoder and a decoder; GPT-2 uses a causal, decoder-only design for text continuation.

02 / REPRESENTING THE INPUT

From text to embeddings

Neural networks work with numbers, not written words. The embedding stage gives each token a numerical representation and adds information about its position.

  1. Tokenize the text. A tokenizer splits a prompt into pieces and assigns each piece an ID. A word is not necessarily one token: uncommon words and misspellings often split into smaller fragments. GPT-2 has a vocabulary of 50,257 tokens; the split and IDs are determined by its tokenizer, not chosen anew for each prompt.
  2. Look up a token vector. Each ID selects a learned row from the token-embedding matrix. GPT-2 small uses 768 numbers per token, so its 50,257 × 768 lookup table contains about 38.6 million parameters. Training adjusts these vectors to capture useful patterns in how tokens are used.
  3. Add position information. Word order matters. GPT-2 learns a separate position-embedding table, allowing the model to distinguish a token near the beginning from the same token later in the sequence. Other model families may encode position differently.
  4. Combine the two. Adding the token vector and its position vector produces the representation that enters the first block.

Input representation = token embedding + position embedding

Look above: expand Embedding to inspect token IDs and position information. The pruning presets leave these input embeddings unchanged. The colored vector textures show measured samples, not all 768 dimensions.

03 / PROCESSING THE SEQUENCE

Transformer blocks

GPT-2 small passes the sequence through 12 transformer blocks. Each block contains multi-head self-attention and a feed-forward MLP, along with normalization and residual shortcuts. A block receives the current representation of every token and produces an updated representation for the next block.

The two main operations have different jobs: attention mixes information between tokens, while the MLP transforms the features of each token separately. Repeating them lets later layers work with information assembled by earlier ones.

Layer is not head: changing Layer selects a transformer block; changing Head selects one attention head inside that block. Navigating the diagram only changes what you inspect. It does not skip layers in the actual model.

04 / SHARING INFORMATION

Multi-head self-attention

Self-attention lets a token gather information from the sequence around it. Different heads can learn different patterns of interaction, although heads do not come with fixed, human-assigned roles such as “grammar” or “meaning.” GPT-2 small uses 12 heads per block, with 64 dimensions per head.

Query, Key, and Value: three views of a token

Learned linear projections turn each normalized token representation into a Query (Q), a Key (K), and a Value (V). A search analogy helps:

Query
What information is this token looking for? Think of the search request.
Key
What information can another token be matched on? Think of a result's searchable description.
Value
What content should be passed along if that token is selected? Think of the result's content.

How one attention head is computed

  1. Compare queries and keys. QKᵀ produces a score for each query and key pair. Dividing by the square root of the head dimension keeps the score scale more manageable. In GPT-2 small, that dimension is 64.
  2. Hide future positions. A causal mask blocks positions to the right of the query. Those scores become negative infinity before softmax, so a token cannot use future text when predicting what follows it. A position may attend to itself and earlier positions.
  3. Convert scores to attention weights. Softmax produces nonnegative weights that sum to one in each row. These weights describe how strongly the query combines the available values; they are not next-token vocabulary probabilities.
  4. Combine the values. Multiplying the weights by V creates the head's output. The outputs from all 12 heads are concatenated and passed through a learned output projection.

Attention(Q, K, V) = softmax(QKᵀ / √d + causal mask) V

Look above: click the attention matrix to expand scores, the causal mask, and softmax. With Head masking selected on the Pruned side, head 1 is masked in every layer. Its attention can still be visible, but its output contribution is zero. Heads 2 through 12 are not masked.

05 / REFINING EACH TOKEN

The MLP: a feed-forward network

After the attention update, the MLP applies the same learned network to each token independently. Unlike attention, it does not directly combine different token positions. It works on features in a representation that already contains contextual information.

In GPT-2 small, one linear transformation expands the vector from 768 to 3,072 dimensions. A nonlinear GELU activation lets the network express more complex transformations than a single linear map. A second linear transformation brings the result back to 768 dimensions, ready to be added to the residual stream.

06 / CHOOSING WHAT COMES NEXT

From representations to output probabilities

After the final block and layer normalization, a vocabulary projection produces one score, called a logit, for each of GPT-2's 50,257 possible tokens. Softmax converts those scores into a distribution whose probabilities sum to one across the whole vocabulary.

The last input position predicts the first token of the continuation. Selecting an earlier position inspects what could follow that earlier prefix. The next-token process repeats as generation extends the sequence.

Read the chart carefully: it shows only the top candidates, without rescaling them to sum to 100%. “Other tokens” accounts for the remaining vocabulary. The expanded view labels log probabilities as log p, not raw logits. A confident prediction is not evidence that a statement is true.

Background: temperature, top-k, and top-p sampling

Many language-model applications sample the next token rather than always taking the highest-scoring option. These settings alter that selection process:

  • Temperature: for a positive temperature T, divide logits by T before softmax. T = 1 leaves the distribution unchanged; values below 1 sharpen it, while values above 1 flatten it. Lower temperature alone does not make sampling fully deterministic.
  • Top-k: sample only from the k highest-probability tokens, renormalizing within that candidate set.
  • Top-p: sample from the smallest leading set whose cumulative probability reaches a chosen threshold p, again renormalizing within that set.

These are general concepts, not controls on this page. This lab uses greedy decoding with repetition penalty 1.1 and a no-repeated-3-grams rule. The chart shows raw model probabilities before those repetition controls, so the continuation may differ from the chart's top candidate.

07 / THE SUPPORTING PARTS

Normalization, residual connections, and dropout

Layer normalization keeps feature scales manageable

Layer normalization normalizes a token's features and applies learned scale and offset parameters. It helps stabilize optimization. GPT-2 uses a pre-normalization design: normalization comes before attention and before the MLP, with one more normalization after the final block. It also remains part of inference.

Residual connections preserve a running representation

Instead of replacing the representation with each sublayer's result, a residual connection adds an update to it. These shortcuts help information and training gradients move through a deep network. In a simplified GPT-2 block, with inference-time dropout inactive:

u = x + Attention(LayerNorm(x))
y = u + MLP(LayerNorm(u))

This running representation is often called the residual stream. Bypassing a whole block preserves that stream by setting y = x; it is not the same as replacing the whole block's output with zeros.

Dropout is a training technique, not permanent pruning

During training, dropout randomly zeros selected activations or attention weights and rescales the surviving values. It discourages reliance on a narrow set of signals. Standard dropout does not permanently erase the model's learned parameters. It is switched off during this lab's inference runs, unlike a pruning mask that is deliberately kept active for a comparison.

08 / REMOVING CONTRIBUTIONS

What is pruning?

Pruning removes or suppresses selected parts of a neural network. Depending on the method, those parts may be individual weights, attention heads, or entire blocks. The aim is often to reduce computation or storage while retaining useful behavior. Whether that succeeds depends on what is removed, how the model is implemented, and how quality is evaluated.

Here, pruning is a reversible experiment: compare the original model with a masked version on the same input. The presets do not retrain the model or automatically repair its behavior.

WHOLE BLOCK

Layer bypass

Layer 1's effective output becomes its input. Attention and MLP updates from that block are discarded, while later blocks still run.

In the diagram: the bypassed block is transparent with an orange dashed contour. On later layers, its orange 3D background card remains visible and can take you back to layer 1.

ONE HEAD PER LAYER

Head masking

Head 1's output is zeroed in every block, before the heads' concatenated output is projected. The other 11 head outputs in each block are left unmasked.

In the diagram: the masked head can retain a normal attention map, but the values it contributes to the next stage are zero. This is one masked head per layer, not one head in the whole model.

SMALL MLP PARAMETERS

Magnitude pruning

Mask the smallest-magnitude parameters in each targeted MLP tensor, aiming for 20%. The working hypothesis is that small values may be less important. However, small magnitude does not guarantee a parameter is dispensable.

In the diagram: coral tiles identify masked positions. Threshold ties can make the achieved fraction differ slightly from the target.

RANDOM MLP PARAMETERS

Random pruning

Mask MLP parameters at random with a target rate of 20%, using a fixed seed for repeatability. This provides a comparison that does not select parameters by magnitude.

In the diagram: different positions are masked from magnitude pruning. The actual fraction can vary because positions are sampled randomly.

Masking is not automatically compression or acceleration

This lab's zeroed parameters still occupy dense tensors. Bypassed blocks and masked heads are still computed internally before their contributions are discarded or zeroed. These experiments therefore do not establish a smaller checkpoint or a speed or memory improvement. Physical removal, suitable sparse kernels, and sometimes recovery training are separate steps.

The 20% settings apply to the targeted MLP parameters, not 20% of the entire model. A change in next-token probabilities or one completion is also not a reliable measure of general model quality; that requires representative tasks and careful evaluation.
